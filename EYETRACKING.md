# Eye-tracking setup and porting guide

## Architecture

1. `Assets/TobiiPro/ScreenBased/Scripts/EyeTracker.cs` receives Tobii samples. Code under `Assets/TobiiPro` is primarily vendor integration.
2. `Assets/EyeTracking/GazePipeline.cs` converts each individual sample to a screen ray and classifies its 2D/3D collider hit. It supports binocular gaze and valid-eye fallback.
3. `Assets/ScreenBasedSaveData.cs` records that immutable sample/hit pair. `GazeTrail` is visualization only and is not a source of scientific hit labels.

Every important stimulus needs a collider and a `GazeTarget` on that object or a parent. Assign a stable ID such as `item_03_value`; do not use display text or a transient clone name as the analysis identity. Dynamically generated value and weight regions receive IDs in `BoardManager.generateItem`.

The task uses `BoxCollider2D`, so classification queries 2D physics first. A 3D fallback supports older scenes. In production, put targets on a dedicated layer and set the saver layer mask to prevent unrelated colliders from occluding them.

## Calibration

Press `Ctrl+Shift+C` to start the configured nine-point calibration from any task scene. A persistent runtime owns the tracker, calibration controller, overlay, and reversible calibration pause. It freezes task time and participant input, uses unscaled time, and restores the exact previous time scale after success. Failure leaves the task paused and displays:

- **Re-calibrate** — repeat calibration.
- **Ignore and continue** — log the decision and resume.

Results and operator choices are written to the timestamp log. With no device connected, the failure prompt allows local testing of the ignore path.

### Local mouse simulation

Select `Assets/Resources/EyeTrackingSettings.asset` and enable **Use Mouse Simulation**. This one setting applies in every scene, including `SetUp`, which has no `[SaveData]` object. In scenes with a `[SaveData]` object, enable **Save Data** to record gaze and show the target overlay. Keep **Save Locally** enabled to inspect XML. The mouse position in the Game view then produces one gaze sample per Unity frame, through the same hit classifier and output writer as Tobii samples. A small Game view box shows the latest target ID or `No hit`. Samples have `GazeRaySource="MouseSimulation"` and `Simulated="True"`; they have no Tobii raw gaze element. This tests coordinate mapping, collider hits, target IDs, and file output, but does not model Tobii accuracy, sampling rate, or sample loss.

The same global toggle makes `Ctrl+Shift+C` run the nine-point calibration display without Tobii hardware, including in `SetUp`. Play does not start calibration automatically. **Simulated Calibration Succeeds** on the settings asset controls its result. Checked: the task resumes automatically after the ninth point. Unchecked: the failure prompt offers **Re-calibrate** and **Ignore and continue**. The task timer and participant controls remain paused until success or Ignore. Calibration events are marked `Simulated` in the timestamp log.

To test in the editor, start from `SetUp`, then enter a test ID and proceed to `Trial`. All nine task scenes are enabled in the shared build scene list. The automatically created `[EyeTrackingRuntime]` must remain present across scene changes. Save gaze and calibration events under a test participant ID, and do not combine simulated and participant files. Turn **Use Mouse Simulation** off in `EyeTrackingSettings.asset` before hardware data collection on Windows.

All generated output uses `Application.persistentDataPath/StudyData/<session>/`. Task results and calibration events are stored in the session directory; gaze XML is stored in its `EyeTracking` subdirectory. The resolved session directory is logged when the participant session starts. `Assets/DATAinf` is input-only.

## Output and the DHive extension point

Local XML is written to `Application.persistentDataPath/StudyData/<session>/EyeTracking`, created automatically. On `[SaveData]`, `_saveLocally` controls whether local XML is written. There is no legacy output-path fallback.

Schema version 2 adds participant, scene, block, trial, gaze-ray source, explicit hit validity, stable target ID, hit object, hit point and collider bounds per sample. `GazeRaySource` is `Binocular`, `LeftEye`, `RightEye`, or `Invalid`. The supplied `Example` files contain legacy fields generated by code/conversion not present in this commit.

For DHive, create a `MonoBehaviour` implementing `IGazeDataSink` and assign it to `_additionalSinkBehaviours`. It receives the same `GazeSampleRecord` as local XML. Local storage can remain enabled for fan-out or be disabled. DHive transport/authentication/retry is deferred until its requirements are supplied.

## Porting and validation checklist

- Copy the screen-based Tobii integration, `Assets/EyeTracking`, and `ScreenBasedSaveData.cs`. `EyeTrackingRuntimeBootstrap` creates the persistent runtime automatically; individual scenes do not need calibration or eye-tracker prefabs.
- Add stable `GazeTarget` IDs and correctly sized colliders to all areas of interest.
- Configure the target layer mask and verify camera, Canvas, resolution, aspect ratio and display mapping.
- Set Unity Asset Serialization to **Force Text**; current task scenes/resource prefabs are binary and cannot be audited reliably in Git.
- Without hardware, test file lifecycle and calibration failure/ignore. Real Tobii validation is still required.
- Before collection, overlay collider bounds at deployment resolution, test monocular fallback, and soak-test 300 Hz recording for sample loss.

See `issues.md` for discovery evidence and `implementation_plan.md` for the layered plan and deferred work.
